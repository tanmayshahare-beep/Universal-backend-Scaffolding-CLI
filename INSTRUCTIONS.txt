━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  PART 1: FIRST-TIME SETUP (DO THIS ONCE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1 — Install dependencies
  Open a terminal IN THE SKELETAL-DOCK FOLDER and run:
  > npm install

Step 2 — Configure your backend (choose one method)

  METHOD A — Desktop GUI Wizard (recommended)
  ─────────────────────────────────────────────
  > npm run gui

  A desktop window opens. On the left sidebar, click any
  feature to open its settings. Use the toggle switch on
  each feature panel to enable or disable it.

  Top bar:
    "browse" — pick your frontend project folder.
               The SDK will be auto-copied there on Generate.

  When you are done:
    Click  [ Generate & Inject SDK ]  at the bottom.
    This writes skeletal.config.json and skeletal-client.js,
    and copies the SDK into your frontend folder.

  Then click  [ Start Server ]  to launch the backend,
  or run:  npm start  in a separate terminal.

  Theme: click [light mode] / [dark mode] in the top-right
  corner to switch between pure-black and pure-white themes.

  METHOD B — Terminal Wizard
  ──────────────────────────
  > npm run setup

  The wizard will ask you:
  - Project name and port (default: 3001)
  - MongoDB URI
  - Which features to enable (see full list below)
  - Feature-specific settings
  - Any CRUD models you want
  - Whether to generate the frontend SDK

  At the end it creates:
    skeletal.config.json  — your backend configuration
    skeletal-client.js    — your frontend SDK (if you chose yes)

Step 3 — Start the server
  > npm start

  You will see:
    [skeletal-dock] MongoDB connected
    [skeletal-dock] Server running on port 3001
    [skeletal-dock] Enabled modules: auth, otp, webhooks, crud, ...

  PART 2: RUNNING THE DEMO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A browser-based tester is included that covers every feature.

  Step 1 — Create the demo config (first time only):
    > npm run demo:setup
    This creates skeletal.config.json with demo settings.
    It will ask if you want to set up Gmail for OTP emails.

  Step 2 — Start the backend (Terminal 1):
    > npm start

  Step 3 — Start the demo UI (Terminal 2):
    > npm run demo

  Step 4 — Open in browser:
    http://localhost:3000

  IMPORTANT: Always run these commands from inside the
  skeletal-dock folder, not from your home directory.

  The demo UI has tabs for: Health, Auth, OTP, Webhooks,
  CRUD, Uploads, WebSocket.

  PART 3: USING IN A NEW PROJECT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Copy this entire "skeletal-dock" folder into the new project
     (or keep one copy on your machine and run it as a service)

  2. Open a terminal in the skeletal-dock folder

  3. Open the GUI for THIS project:
     > npm run gui

     In the GUI:
     - Click "browse" and select your frontend project folder
     - Toggle and configure features on the left sidebar
     - Click [ Generate & Inject SDK ] when ready
     - Click [ Start Server ] to launch

  4. Or use the terminal wizard instead:
     > npm run setup
     > npm start

  5. skeletal-client.js is now in your frontend folder.
     Import it in your frontend code and use it.
     (see PART 5 below for examples)

  PART 4: COMMAND REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  npm run gui
    Opens the desktop GUI configurator window.
    Requires Electron (installed via npm install).

  npm run setup
    Runs the full interactive terminal wizard.
    Use this for a new project or to change settings.

  npm start
    Starts the backend server on the configured port.

  npm run demo:setup
    Creates a demo skeletal.config.json.
    Asks if you want to configure Gmail for OTP emails.

  npm run demo
    Starts the demo UI on http://localhost:3000

  node cli/index.js status
    Prints a summary of what's currently enabled.
    Example output:
      Project : my-shop
      Port    : 3001
      MongoDB : mongodb://localhost:27017/my-shop
      ✓  Auth (JWT)
      ✓  OTP Email (Gmail)
      ✗  OTP SMS
      ✓  Webhooks
      ✓  Auto CRUD

      ✓  File Uploads
      ✓  Request Logging
      ✓  WebSocket
      CRUD Models:
        product — name:String, price:Number [auth] [roles: admin] [softDelete]

  node cli/index.js add-model
    Adds a new CRUD model without re-running the full wizard.
    Prompts for: model name, fields (as JSON), auth yes/no,
    roles (if auth), soft delete yes/no.
    Then restart the server to activate.

  node cli/index.js regen-sdk
    Regenerates skeletal-client.js from the current config.
    Run this any time you change the config manually.
    (The GUI does this automatically on Generate.)

  node cli/index.js --help

  PART 5: FRONTEND SDK USAGE EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

After Generate (GUI) or npm run setup (CLI), skeletal-client.js
is in your frontend folder. Import and use it:

  --- AUTH ---

  // Register a new user
  const result = await skeletalAuth.register('user@email.com', 'mypassword', 'Alice');
  // result.user, result.accessToken, result.refreshToken

  // Login
  const result = await skeletalAuth.login('user@email.com', 'mypassword');
  localStorage.setItem('token', result.accessToken);

  // Get current user profile
  const token = localStorage.getItem('token');
  const { user } = await skeletalAuth.me(token);

  // Logout
  await skeletalAuth.logout(refreshToken);

  --- PASSWORD RESET ---

  // Step 1: request reset (sends email if configured)
  await skeletalAuth.forgotPassword('user@email.com');
  // In development (NODE_ENV not set), the token is returned in the response.
  // In production, it is only sent by email.

  // Step 2: set new password using the token
  await skeletalAuth.resetPassword(token, 'newpassword123');

  --- OTP ---

  // Send OTP to email
  await skeletalOTP.send('user@email.com', 'email');

  // Send OTP to phone (Twilio must be configured)
  await skeletalOTP.send('+1234567890', 'sms');

  // Verify the code the user typed in
  const { verified } = await skeletalOTP.verify('user@email.com', '482910', 'email');
  if (verified) { /* proceed */ }

  // Optional: use a purpose tag (e.g. 'password-reset' vs 'signup')
  await skeletalOTP.send('user@email.com', 'email', 'password-reset');
  await skeletalOTP.verify('user@email.com', code, 'email', 'password-reset');

  --- WEBHOOKS ---

  // Register a URL to receive events
  await skeletalWebhooks.register(
    'https://mysite.com/hooks/incoming',
    ['order.created', 'payment.done'],
    'My Receiver'
  );

  // Trigger an event (fires all registered URLs for that event)
  await skeletalWebhooks.trigger('order.created', { orderId: 'abc123' }, token);

  // List all registered webhooks
  const { webhooks } = await skeletalWebhooks.list();

  // Remove a webhook
  await skeletalWebhooks.remove(webhookId);

  --- FILE UPLOADS ---

  // Single file upload
  const form = new FormData();
  form.append('file', fileInput.files[0]);
  const { url, filename } = await skeletalUploads.single(form, token);
  // url is like: /uploads/1234567890-photo.jpg

  // Multiple file upload
  const form = new FormData();
  fileInput.files.forEach(f => form.append('files', f));
  const { files } = await skeletalUploads.multiple(form, token);
  // files is an array of { url, filename, size, mimetype }

  // Access an uploaded file (no auth needed)
  <img src="http://localhost:3001/uploads/1234567890-photo.jpg" />

  --- CRUD (example model: product) ---

  const token = localStorage.getItem('token');

  // Create
  await skeletalProduct.create({ name: 'Widget', price: 9.99, inStock: true }, token);

  // List (with pagination and filtering)
  const { data, total } = await skeletalProduct.list({ page: 1, limit: 10 }, token);

  // Get one
  const { data } = await skeletalProduct.get('64f...id', token);

  // Update
  await skeletalProduct.update('64f...id', { price: 12.99 }, token);

  // Delete (soft delete: marks as deleted, does not remove)
  await skeletalProduct.remove('64f...id', token);

  // Restore a soft-deleted record
  await fetch('/api/product/64f...id/restore', {
    method: 'POST',
    headers: { Authorization: 'Bearer ' + token }
  });

  --- WEBSOCKET (real-time) ---

  // Install socket.io-client in your frontend first:
  // npm install socket.io-client

  import { io } from 'socket.io-client';
  const socket = io('http://localhost:3001');

  // Listen for inbound webhook events
  socket.on('webhook:received', (payload) => {
    console.log('Event received:', payload.event, payload.data);
  });

  PART 7: ADDING A NEW CRUD MODEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Option A — GUI
  Open the CRUD panel, click [ + Add Model ], fill in the
  field table, set auth/roles/soft-delete, click Save Model.
  Then click [ Generate & Inject SDK ] to apply.

Option B — Terminal (without re-running the full wizard):
  > node cli/index.js add-model

  It will prompt:
  ? Model name: post
  ? Fields as JSON: {"title":"String","body":"String","published":"Boolean"}
  ? Require JWT auth? Yes
  ? Restrict to roles (leave blank for any auth user): admin
  ? Enable soft delete? No

  Available simple field types:
    String, Number, Boolean, Date, ObjectId, Mixed, Array

  Advanced field definition (with validation):
    {
      "title": { "type": "String", "required": true, "minLength": 3, "maxLength": 200 },
      "price": { "type": "Number", "required": true, "min": 0 },
      "status": { "type": "String", "enum": ["draft", "published"] }
    }

  After adding, restart the server:
  > npm start

  New endpoints are now live:
    GET    /api/post
    GET    /api/post/:id
    POST   /api/post
    PUT    /api/post/:id
    DELETE /api/post/:id
    POST   /api/post/:id/restore  (only if soft delete enabled)

  PART 8: ROLE-BASED ACCESS CONTROL (RBAC)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Users are created with role: "user" by default.

  To restrict a CRUD model to specific roles, set "roles"
  in the model config (GUI: Roles field in the model editor):

    { "name": "report", "fields": {...}, "auth": true, "roles": ["admin"] }

  A request from a user with role "user" will receive 403.

  To promote a user to admin, update their document in
  MongoDB directly:
    db.users.updateOne({ email: "you@example.com" }, { $set: { role: "admin" } })

  PART 9: SOFT DELETE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Enable per model in the GUI (soft delete checkbox) or in config:
    { "name": "post", "fields": {...}, "softDelete": true }

  How it works:
  - DELETE /api/post/:id  →  sets deletedAt to current time
  - GET    /api/post      →  automatically excludes deleted records
  - GET    /api/post/:id  →  returns 404 if deleted
  - POST   /api/post/:id/restore  →  clears deletedAt, record is visible again

  Deleted records stay in the database and can be restored
  at any time. To permanently remove them, do it directly
  in MongoDB.

  PART 10: FILE UPLOADS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Enable in the GUI (Uploads panel) or set in config:
    "uploads": {
      "enabled": true,
      "destination": "uploads/",
      "maxSizeMb": 5,
      "auth": true
    }

  Endpoints:
    POST /api/uploads/single    — field name: "file"
    POST /api/uploads/multiple  — field name: "files"

  Files are stored in the destination folder and served at:
    GET /uploads/<filename>

  The uploads folder is created automatically on server start.
  If "auth" is true, a valid JWT token is required to upload.

  PART 11: RATE LIMITING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Enable in the GUI (Rate Limit panel) or set in config:
    "rateLimit": {
      "enabled": true,
      "globalMax": 100,
      "authMax": 20,
      "windowMs": 900000
    }

  globalMax — max requests per window for all /api routes (default 100)
  authMax   — stricter limit applied to /api/auth/login and
              /api/auth/forgot-password (default 20)
  windowMs  — window in milliseconds (900000 = 15 minutes)

  When a limit is exceeded the server returns:
    429 { "error": "Too many requests, please try again later." }

  If you hit rate limits during development, increase the
  limits in the GUI or in skeletal.config.json and restart.

  PART 12: CONFIGURING EMAIL (GMAIL APP PASSWORD)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Gmail is the easiest option — no SMTP server knowledge needed.

  1. Go to myaccount.google.com/security
  2. Turn on 2-Step Verification (required)
  3. Search "App passwords" → create one → copy the 16-char code
     (spaces in the code are fine, they are ignored automatically)

  In the GUI: go to OTP panel → Email Channel → select Gmail App Password.
  Enter your Gmail address and the 16-character code.

  In the terminal wizard: choose "Gmail App Password" when asked
  for the email provider. Enter:
    Gmail address : youraddress@gmail.com
    App Password  : the 16-character code

  Gmail is used for:
  - OTP email codes
  - Password reset emails

  For other providers (Outlook, SendGrid, etc.):
  Choose "Custom SMTP" and enter host, port, user, password.

  PART 13: PASSWORD RESET FLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  POST /api/auth/forgot-password   { email }
    - Generates a reset token (expires in 1 hour)
    - Sends the token by email if email is configured
    - In development (NODE_ENV not set to "production"),
      the token is also returned in the response so you
      can test without email configured
    - Always returns the same generic message to prevent
      user enumeration

  POST /api/auth/reset-password    { token, newPassword }
    - Validates the token and expiry
    - Updates the user's password
    - Invalidates the token immediately after use

  To hide the token from responses in production:
    Set NODE_ENV=production in your .env file

  Create a .env file in this folder (copy .env.example):

  PORT=3001
  MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/dbname
  NODE_ENV=production

  These override the values in skeletal.config.json.
  NODE_ENV=production hides the dev-only reset token from
  password reset responses.

  PART 16: ALL API ENDPOINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Base URL: http://localhost:3001/api

  GET  /api/health                      → server status check

  POST /api/auth/register               → { email, password, name }
  POST /api/auth/login                  → { email, password }
  POST /api/auth/refresh                → { refreshToken }
  POST /api/auth/logout                 → { refreshToken }
  GET  /api/auth/me                     → header: Authorization: Bearer <token>
  POST /api/auth/forgot-password        → { email }
  POST /api/auth/reset-password         → { token, newPassword }

  POST /api/otp/send                    → { target, type, purpose? }
  POST /api/otp/verify                  → { target, code, type, purpose? }

  POST   /api/webhooks/register         → { url, events?, label?, secret? }
  GET    /api/webhooks                  → list all
  DELETE /api/webhooks/:id              → remove one
  POST   /api/webhooks/trigger          → { event, data }  [auth required]
  POST   /api/webhooks/inbound          → receives signed webhook payloads

  POST /api/uploads/single              → multipart, field: "file"
  POST /api/uploads/multiple            → multipart, field: "files"
  GET  /uploads/<filename>              → serve uploaded file (static)

  GET    /api/<model>                   → list (paginated, filters)
  GET    /api/<model>/:id               → get one
  POST   /api/<model>                   → create
  PUT    /api/<model>/:id               → update
  DELETE /api/<model>/:id               → delete (or soft-delete)
  POST   /api/<model>/:id/restore       → restore soft-deleted record

  PART 17: TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  GUI won't open
    → Run: npm install  (Electron must be installed first)

  "No skeletal.config.json found"
    → Click Generate in the GUI, or run: npm run setup

  "MongoDB connection failed"
    → Check your MongoDB URI is correct and MongoDB is running
    → For Atlas, whitelist your IP in Network Access

  OTP email not sending
    → Make sure you used an App Password (not your Gmail password)
    → Check 2-Step Verification is on in your Google Account

  CORS errors in browser
    → Re-run setup / click Generate and add your frontend origin
      (e.g. http://localhost:3000 or https://yoursite.com)

  "Cannot find module" errors
    → Run: npm install

  skeletal-client.js is out of date
    → Click [ Generate & Inject SDK ] in the GUI, or run:
      node cli/index.js regen-sdk

  429 Too many requests during testing
    → Increase globalMax or authMax in the Rate Limit panel (GUI)
      or in skeletal.config.json, then restart the server

  Upload fails immediately
    → Make sure the server has been started at least once
      (it creates the uploads folder on startup)

  Password reset token not in response
    → NODE_ENV=production hides the token for security
    → Remove that env var or set to "development" for testing

  "node demo/server.js" says module not found
    → You are in the wrong folder. Run:
       cd "C:\path\to\skeletal dock"
       npm run demo
